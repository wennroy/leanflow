# 验证与收尾

供 execute、review、verify、finish 按需引用；这里只维护一套规则。
验证、复审、人工验收和归档各有完成条件，命令返回不代表 feature 完成。
用户明确指定的范围、确认要求和已有裁决优先；不重复索取已有授权。

## 状态与续跑

- plan 的 checkbox 表示任务验收完成，不代表 feature 已复审或已归档。
- `执行记录` 简记当前阶段、验证证据、复审结论和用户裁决；没有该节的旧
  plan 在首次 execute 时补上。状态可用：进行中、待裁决、待验收、阻塞、已完成。
- 首次 execute 记录基线提交和已有工作区改动。只处理本次任务的改动；
  无关改动保留原样，只有确实冲突或归属不清时才问用户。
- 只有尚未实施的计划可以用当前 HEAD 建立基线。旧 plan 已有任务改动或
  提交却缺基线时，先按任务提交、分支或既有记录回溯首次实施前的起点；
  无法确定时询问，不能把恢复时的 HEAD 当成起点而漏掉已完成的任务。
- 每项验证记录命令、结果和对应代码状态（提交号及未提交改动，包含
  未跟踪代码）；复审记录范围、对应代码状态、结论及各项处置。
- 续跑先核对代码与记录。从待办阶段继续：已有复审等裁决、已实施等人工
  验收、已通过等归档，都不重新实施任务。
- 仅勾选进度、补验证记录、移动归档路径不使代码证据失效。需求、验收
  标准、代码、依赖或相关环境有变化时，重新验证或复审受影响部分；
  无法确定旧证据是否仍有效时，也须重新检查。

## 验证

1. **需求与任务**：对照需求来源、目标、关键决定及每项验收结果，确认实现
   覆盖了需求。命令成功只能证明它检查的内容；缺少覆盖的验收点须补证据。
2. **自动验证**：执行对应任务和 plan 的全局验收命令；无 plan 时根据实际
   diff 选取相关检查，说明验证范围。命令、被检查内容和环境均未变时，
   可以复用已记录的成功结果，不因切换命令而重复跑整套检查。
3. **改动范围与残留**：检查 diff 是否超出目标、有意外修改或临时调试代码。
   `console.log`、`TODO` 等只是检查线索，结合上下文判断，不能见到就要求删除。
   发现问题集中列出；明确属于本次实施的错误可修，改变产品取舍须由用户决定。
4. **人工验收**：明确区分已实施与已验收。未得到用户确认的 `[人工]` 项
   保持未勾选；把已可验收的项目集中列出。它们不阻止无依赖的实现、验证
   和复审，但会阻止最终归档。
5. **报告**：给出通过、失败、未验证或待人工确认及对应证据。失败可按 debug
   方法定位；没有执行或无有效结果时，不得称验证通过。

Stop hook 的提醒、静默或退出码都不能替代这里的验证证据。

## 复审是否已完成

- execute 在实现和自动验证完成后，按 `commands/review.md` 做一次独立
  复审。人工项目已实施即可先审，不需要等用户完成所有人工验收。
- 复审问题集中呈现，由用户裁决：修、延期、不修；记录裁决并执行已同意
  的修复。等待新裁决时保留状态；已获裁决的项目不重复询问。
- 修复后验证受影响部分，并针对原问题检查修复结果；只有改动使其他区域
  的审查结论失效时才扩大复审，不默认再审整个 feature。
- 所有发现都要有处置记录。仍未解决且未获用户明确接受的阻塞问题，会阻止
  归档；已接受的遗留事项需如实报告，不能描述为「无问题」。
- 用户接受延期且移出当前目标的事项记入「已接受的遗留事项」，不混入本次
  未验收任务；仍属当前目标或影响必需验收的事项不能仅凭「延期」视为完成。
- 续跑时，已有且仍有效的复审结果直接复用。用户明确要求跳过复审时记录
  该决定并说明「未复审」，不能伪造复审通过。

## 归档

仅在 execute 的收尾或用户显式调用 finish 时执行；独立 review / verify
完成后直接报告，不顺带归档项目。

前提：任务均已验收，自动验证结果有效，复审已完成或用户明确要求跳过，
所有人工验收已确认，没有待裁决或未获接受的阻塞项。

- 条件不足：状态记为待裁决、待验收或阻塞，说明具体待办；不标完成、不移动
  plan。有已授权且可继续的工作先完成，缺用户输入时再等待。
- 条件齐备：将状态改为已完成，保留证据与遗留事项，移动至
  `plans/done/<原文件名>`。目标存在时不覆盖，选用新的归档名并说明。
- 只为归档产生的计划文件变更，不要求重新运行业务测试。归档产生的变更须
  在收尾报告中说明；若已有提交授权，可与本次计划记录一起提交，否则保留
  在工作区，不隐瞒为「全部已提交」。
- 整理提交、squash、push、PR、merge、删除分支均按用户明确指令处理。
  自动归档不附带这些动作，也不改变 execute 的逐任务提交规则。

报告用几句话说明完成情况、验证依据、复审处置、归档位置和剩余人工事项。
