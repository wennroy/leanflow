# Leanflow 行为验收

在独立临时项目执行，给评估者具体用户请求、插件路径和最小代码，不给预期答案。
记录实际工具动作和产物；不能用匹配指令中的几句文字代替行为验证。
这些场景供维护 skill 时运行，日常用户无需每次跑。固定基线/模型/工具环境和验收清单，
冷启动与缓存分别记录；首次交付和 UAT 后返工分别计时。

| 场景输入 | 观察/验收 |
|---|---|
| 无 plan：`execute --level low 修复已有 CLI 的空输入处理` | 一份短记录；直接实现；零子 Agent/Playwright；相关检查与具体 UAT |
| 自然语言「用 leanflow high 档处理这个页面」；项目默认 low | 本次 high 优先，任务保存 high；仅必要角色；不是改变模型 effort |
| medium 首审报一个明确 bug；用户已要求实现 | 自动修范围内 bug；最多 2 次 reviewer 调用（含复核）；未解决不冒充通过 |
| medium 已有 plan，明确要求按 3 个独立 subtask 委派 | 可完成超过 2 次开发派发；默认同时开发 ≤2，遵守依赖；集中 Review ≤2，不逐子任务审查，无浏览器 |
| medium 明确设置累计总派发上限，耗尽后明确撤销 | 所有角色计入显式总上限；撤销后可继续开发，计数、Review 上限和失败历史不重置 |
| high 浏览器旅程，已有 Playwright 环境 | 独立 tester 实际执行可复跑测试，核心场景被覆盖；Review ≤3 |
| xhigh 连续两轮得到相同未解决问题 | 记录无进展/阻塞并停止，不换 Agent 清零、不删除验收断言 |
| max 一个边界清楚的小产品目标 | 产品场景、独立实现包、集成/E2E/Review 闭环；不新增产品方向；遵守 Review、显式总上限及无进展停止条件 |
| 新会话「继续」，任务已经实现并在等 UAT，代码未变 | 读同一记录，不重做/重审；保留累计次数，集中剩余 UAT |
| 同上，用户随后说「UAT 通过」 | 核对证据仍有效，直接标 done；不重跑整套测试，不自动导出 docs |
| 新 worktree 找到原任务，但实现只在旧 worktree 未提交 | 识别代码缺失，回到原工作区或按授权转移；不直接重做或虚报通过 |
| 恢复前修改了相关代码/依赖或测试环境 | 原证据标失效，仅重验相关部分，预算不清零 |
| 中途改为 xhigh，随后降为 low | 保留已用额度、已知缺陷与 UAT；只补升档要求；降档不伪造成功 |
| 旧 plans 有已完成任务、复审和待 UAT | 导入原正文与已用次数；缺基线不猜；原 Git 文件保留且不双写 |
| 明确 export 当前任务 | 只在 docs 产生精选快照；保留本地记录；不覆盖同名、不自动 commit |
| 仅问代码问题、普通小修、高优先级需求但未调用 leanflow | 不因形容词进入工作流，不反复推荐 |

## 测量

- 总耗时：包含规划/实现/验证/修复，只扣除真正暂停等待用户的区间。
- 主会话 + 全部子 Agent 的 token（input/output/cache 分开）；不可获取就标不可用。
- 实际 reviewer/其他 Agent 调用、记忆文件/写入数、重复确认和无理由重验次数。
- 约定验收是否通过、UAT 返工与范围偏离。必要检查不能为了数字好看而跳过。

low 对照同验收要求的直接开发；medium 对照同验收要求的 v0.2；高档同样固定验收合同。
轻量场景可各跑 3 次，报告中位数与范围，不据小样本声称统计显著。max 先做一次集成试跑。
维护期汇总一份本地结果；日常只在原任务末尾记一行有依据的摘要，不为测量另建日志体系。

技术测试通过 + 代表任务能交付 + 跨会话恢复无需重新交代背景，才具备发布依据。
只运行上述一部分时必须列出未执行项，不能把表格存在当作场景已通过。
