# /leanflow:execute

先确定 `<plugin-root>`：使用宿主给出的实际安装目录，或从本入口源文件/迁移 Skill 的祖先目录
查找 `.claude-plugin/plugin.json`（name=leanflow）与 `scripts/leanflow.py`。同会话核实后复用；
后文占位符替换成该绝对路径，不依赖 shell 中存在 `CLAUDE_PLUGIN_ROOT`。定位失败报告入口缺口，
不从其他源码目录猜测，不全盘搜索。

读取 `<plugin-root>/references/levels.md`、`references/memory.md` 和
`references/completion.md`（后两者同样相对插件根）。同一会话已加载则复用。
先解析 `$ARGUMENTS` 的 `--level`，剩余部分是需求描述或已有任务 id/路径。

## 1 · 定位与准备

- 明确任务 → show，核对来源 worktree、基线、已有改动、证据与遗留项；本次明确改档才 level。
- 新需求描述 → 内联采用 plan 的澄清/拆分方法，创建一份任务记录，随后继续实施。
  low 短记录即可，不要求用户先调用 plan，也不读取完整规划方法论。
- 无参数 → 按 memory 规则选未完成任务；没有任务才问需求，多个候选才让用户选。
  旧 plans 的恢复按 commands/memory.md 迁移，不把旧任务当新任务重做。
- 启动或改档只汇报一行实际策略，例如「high：Review ≤3 次，核心旅程 E2E」。
- high 以上先检查必要测试环境能否运行；缺凭据/环境只阻塞依赖项，继续独立工作。
- max 若缺产品场景，按预算调用 product；复用已确认的场景，不重复做需求探索。

## 2 · 实施

low 全部内联，不调用任何子 Agent 或 Playwright。medium 以上按 plan 的任务结构和用户指示
选择委派或内联；用户已要求按 subtask 委派就按既有安排执行，无需升档或重复确认。
按可验收批次开发、运行相关检查，批次完成时写回；不为每个微小步骤新建文件、派 Agent 或提交。
失败按 commands/debug.md 定位，只补受影响的检查；遵守失败与无进展停止条件。

medium/high/xhigh 有适合委派的任务时、max 有足够独立工作时，按任务派 implementer：

1. 先 `reserve <id> implementer`，再调用宿主 Agent 工具；每次新工作请求都预留。
2. 按需读 agents/implementer.md，给任务、文件归属、目标/决定、验收和必要接口上下文，
   不转发整段会话。一个清晰独立的 subtask 可以单独委派，紧密关联的小任务合并；
   开发派发不消耗 Review 额度，总次数默认只统计。用户明确设置总上限时遵守该上限。
3. 并发最多 2 个实现包，且不超过宿主可用额度；只有无文件/接口/数据/状态冲突才并行。
   没有隔离条件时顺序执行。工作区共享不等于上下文共享，主会话不同时改这些文件。
4. 主协调者核对结果、整合代码、验证组合行为并更新任务记录，子 Agent 不写状态或提交。
   在集成后的可验收批次集中 Review，不为每个 subtask 默认附加 Reviewer；高风险任务
   需要提前审查时也消耗同一需求的 Review 额度，不能按子任务重置。

范围内明确 bug 自动修复；改变产品取舍、方向或放弃验收项集中询问。
可逆的实现调整按事实更新任务记录，不反复确认。按完整改动批次提交，仅暂存本任务文件。

## 3 · 分档验证与收敛

- low：相关低成本检查后准备 UAT，记「按 low 未复审、未运行 Playwright」。
- medium：相关无浏览器检查后按 commands/review.md 首审、修复与定向复核；低成本检查
  不覆盖原故障就留具体 UAT，不默认启动 Playwright，用户显式指定的检查按 levels 处理。
- high/xhigh：按 agents/tester.md 预留并派 tester，产出可复跑的旅程测试并实际运行。
  按 review 方法审查完整改动（包含新增测试），修复后重验/复核受影响部分。
- max：product 场景 → 独立实现包 → 集成 → tester / reviewer → 修复循环。
  最后对照整体目标和场景表核对成品；复用已有产品结论，必要的新产品核对也计入总派发统计，
  有用户显式总上限时消耗总额度。

每一轮以有效问题和验收缺口为输入，解决后才关闭；不通过删断言、skip、缩小需求求绿。
xhigh/max 尽量处理全部范围内有效问题，但受 Review 上限、显式总上限与无进展停止条件约束。
任何档位都不能把预算耗尽当作验收通过。无额度的必需复核记待办，不继续偷偷派发。
不要为重新进入本命令而重跑完整流程。

## 4 · UAT、交付与恢复

按 completion 规则在交付 checkpoint 一起保存 --checks，并依据返回的 delivery 报告缺口。
已实施但未验收保持 awaiting_uat，不等于自动必需项通过；用户报告缺陷时返回相应阶段，
保留累计次数。仅收到 UAT 通过、证据仍有效且其他必需项已满足时直接更新和收尾。
满足条件标 done，原地保留唯一任务记录。需要发布则按既有授权执行并保留发布后检查结果。
结束前记录下一步；有实际使用数据时只留一行耗时/Agent/记忆写入摘要，拿不到 token 就记不可用。
max 第一版仅在当前会话循环；中断靠本地记录恢复，不宣称后台持续运行。
