# /leanflow:debug

一页纸调试法。不追求流程完整，追求**先复现再动手**。
适用于原因未知的报错、回归或异常行为，可独立调用，也可由 execute 在验证
失败时读取使用。内部调用沿用失败命令与已有证据，不要求用户再输入 debug。

## 步骤

1. **稳定复现**：把「$ARGUMENTS」描述的现象变成一条可重复的路径
   （命令、操作序列、最小输入）。复现不了 → 先解决复现，不猜。
2. **最小化**：砍掉与现象无关的部分，定位到最小触发单元
   （一个函数、一个请求、一个配置项）。
3. **假设**：写下 1–3 个假设，按可能性排序；每个注明
   「验证它要看什么证据」。
4. **验证与修复**：从最可能的假设开始验证；确认根因后修，
   **只修根因**，不顺手重构。
5. **回归**：用能覆盖原故障的验证证明修复；适合自动化且能防止回归时补测试，
   跑受影响的检查。记录命令、结果及验证范围，不把测试数量当修复依据。

## 规则

- 每步一行记录假设和证据；假设证伪就回退，不硬撑。
- 3 个假设全部证伪 → 汇总证据和阻塞原因，停止盲目尝试；内部调用返回执行者，
  不清空已有尝试记录重新计数。确实缺用户输入时说明所缺信息。
- 独立调用修完后报告根因、改动和验证；内部调用返回原任务继续验证与收尾。
  同类问题仅在有证据且影响当前范围时继续检查，范围外问题列为建议。
